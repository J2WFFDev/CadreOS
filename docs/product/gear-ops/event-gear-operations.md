# GearOps Event Gear Operations Guide

This guide is for event staff and leads using **Events → [Event] → Gear**.

## When to Use This

Use this for planning, staging, deploying, recovering, and closing event gear operations.

## 1) Build the Event Gear Plan

- Create/update plan status.
- Set deployment context.
- Set default staging and recovery locations.
- Add checklist/staging/recovery notes.

## 2) Define Requirements

Add requirement rows with:
- label
- type (required/optional/support)
- quantity needed
- preferred category (optional)
- notes

## 3) Assign Specific Inventory Items

For each requirement:
- choose available inventory item
- avoid items with conflicting custody/assignment states
- fill requirement gaps before staging

## 4) Verify Event Readiness

Use readiness summary to review:
- ready
- limited-use
- unavailable
- out-of-service
- maintenance-needed
- missing/not assigned

Replace non-ready critical items before departure.

## 5) Stage Gear

- stage from current storage toward event staging state
- keep staging location data accurate

## 6) Deploy (Issue)

- use rapid checkout or item checkout links
- deployment custody remains in checkout workflows

## 7) Recover After Event

1. return/check in custody records
2. complete event recovery
3. capture recovery condition
4. set maintenance flag and notes when needed
5. restore storage location

## 8) Complete Post-Event Review

Review:
- requirement gaps
- still deployed/unreturned
- returned-awaiting-recovery
- event-linked custody and consumable activity timeline

## 9) Missing, Damaged, or Maintenance-Needed Gear

- missing/unreturned: keep in exception follow-up until resolved
- damaged: record condition + recovery notes + maintenance log
- maintenance-needed: set flag and route to readiness/maintenance workflow

## Offline/Pending Note

Event plan/requirement/assignment setup has online-required boundaries in current RC scope. Staging/recovery may queue locally but remain unconfirmed until sync.
