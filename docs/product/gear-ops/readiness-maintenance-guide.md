# GearOps Readiness and Maintenance Guide

Use this guide for staff verifying deployability, condition, and service lifecycle.

## When to Use This

Use this before issue/deployment, after return, and during periodic inspections.

## Readiness States

- **Ready**: deployable now.
- **Needs inspection**: inspect before next issue/deployment.
- **Maintenance required**: maintenance action needed.
- **Not ready**: blocked from operational deployment.
- **Decommissioned**: removed from active service.

## Condition States

Condition reflects item quality (for example good/fair/poor/damaged). Poor or damaged should trigger inspection or maintenance follow-up.

## Maintenance Workflow

1. Create maintenance log entry (intake).
2. Capture service notes and condition before/after.
3. Complete service and return item to active state when ready.
4. Keep history intact for audits and post-incident review.

## Return Inspection Guidance

When receiving gear:
- verify condition on return
- compare against expected return state
- create maintenance entry immediately if concerns found

## Event Recovery + Maintenance

During event recovery:
- set condition on recovery
- use maintenance flag when follow-up is needed
- add recovery notes with concrete findings

## Readiness Decision Rules for Operators

Do not deploy items that are:
- in maintenance
- out of service
- blocked by unresolved condition concerns
- blocked by active conflicting custody

## Quick Example

“Helmet returned cracked”:
1. Check in return with condition note.
2. Create maintenance log.
3. Keep item out of active deployment until maintenance clears readiness.
